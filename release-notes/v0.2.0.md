## Reeframe backend v0.2.0

The first public release. Since v0.1.0, which only recorded cameras, Reeframe has grown into a full VMS backend with automation built in.

### What's new since v0.1.0

- **Pipelines.** Triggers (schedule, camera and external events, system signals, manual runs, CPU, RAM and disk thresholds) run actions such as `extract_clip`, `snapshot`, `start_recording`, `transcode` and `watermark`, with conditions and forks, and deliver results to local disk, S3, SFTP, SMB, email, Slack, Telegram or a webhook. Pipelines reload without a restart.
- **Event sources.** Home Assistant over its WebSocket API, MQTT, inbound webhooks, API polling and file watchers.
- **Live view.** A built-in RTSP relay serves each camera's sub stream by default, falling back to the main stream when there is none.
- **Clips with lead-in.** An in-memory pre-event buffer lets `extract_clip` start before the event that triggered it.
- **Detection and previews.** Optional motion, scene-change and tamper detection, and optional scrub-preview thumbnails.
- **Recordings.** Playback and export over HTTP, retention by age and by disk usage, daily coverage summaries per camera time zone, and repair of unfinished chunks after a crash.
- **Access.** Local users with JWT and API keys, or tokens issued by the Reeframe Coordinator.
- **Operations.** Prometheus metrics, OpenTelemetry tracing, health probes, and settings changeable through the API.

### Lighter by default

A camera now only runs what something asks for. Recording and live view copy the stream without decoding it, and the sub stream, motion detection and thumbnails start only when a camera setting or a pipeline needs them. Recording a 1080p camera at 4 Mbps costs about 1.9% of one CPU core and 3.4 MB per camera. See [docs/benchmark.md](https://github.com/reetmlabs/reeframe-backend/blob/main/docs/benchmark.md).

### Fixed

- Recording could report as started but never write a file, and starting a recording could fail with a 500 when two requests raced.
- Stopping a recording no longer reconnects the camera or closes its last chunk twice.
- Recording-only cameras no longer reconnect once on start.
- Changing a camera's stream URL or credentials now takes effect without a restart.
- Thumbnails are written reliably and skip black or white frames from a lost feed.
- The Docker image, `docker-compose.yml`, the `.deb` package and the systemd unit now build and start as documented.

### Upgrading from v0.1.0

- Database migrations run automatically on start.
- `VMS_AUTH__JWT_SECRET` is required alongside `VMS_ENCRYPTION_KEY`. Generate it with `openssl rand -base64 32`.
- Motion detection and thumbnails are off for every camera until you turn them on (`motion_detection_enabled`, `thumbnails_enabled`). Pipelines with a camera event trigger still turn motion on by themselves.
- `POST /cameras/{id}/relay/start` without `quality` now returns the sub stream, and its response includes the `quality` it used.
- The RTSP relay listens on port 8554, and the Docker image exposes it.

### Known limitations

- The RTSP relay has no authentication. Keep port 8554 on a trusted network; see [SECURITY.md](https://github.com/reetmlabs/reeframe-backend/blob/main/SECURITY.md).
- In Docker, relay URLs contain the container's address ([#94](https://github.com/reetmlabs/reeframe-backend/issues/94)).
- After a recording stops, the camera's main stream stays connected until the camera stops ([#95](https://github.com/reetmlabs/reeframe-backend/issues/95)).
- PTZ, alarm outputs and stream quality switching are not implemented yet.
